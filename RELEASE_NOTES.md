# Worker 0.1.0+53e0802f

## What changed since worker-v0.1.0-ad90ce4cb54f

- Scheduler: a repository refusal is recognized by every key the worker's pre-flight can name
- Daemon: a stray rejection ends the worker again, as Node ends it
- Self-test: a contributor can turn it off, with "selfTest": false in the config
- Daemon: a malformed standing answer no longer ends the worker, nor does any promise nobody awaited
- Self-test: a failed task's hold lasts until its check has answered
- Self-test: a fault is checked again within the hour, and a limit that lasts is asked about less often
- Self-test: a restart within a day of a pass on the same CLI and premium model takes work at once
- Self-test: a premium model the account refuses is replaced by the approved alternative that runs the command
- Execution: the build is read at every depth, where forge writes a contract that shares its file's name
- Self-test: a worker reads its runtime's failures from the plane's own lists, never from the task's text
- Protocol: ./** is refused as ** is, and budget checks read a leading ./ as workers do
- CI: a change that reaches the verifier's analysis gate is checked with Slither installed
- The token list stays off until TOKEN_LIST_ENABLED, and lists only mainnet tokens not passing as IMD
- Planner: steps given ./src/** and src/** may not run at once, as workers read both as src/**
- Scheduler: a premium model the account was refused keeps contract work away for a day, not a month
- Foundry guard: the compiler or solver forge runs must be a name, not a path the tree chose
- Foundry guard: every path forge writes to stays inside the checkout
- Foundry guard: forge's config is read from stdout, so a warning neither refuses nor resets it
- Contract work skips a machine whose plan refuses its premium model
- Foundry guard: forge's warnings no longer refuse a repository or hide its via_ir setting
- Daemon: a Codex run that dies without an error reports what it printed, the agent's words marked
- Daemon: the compiler an agent pinned is installed before the local build, in half the time left
- Daemon: a prior-work conflict says what happened instead of blaming plan validation
- Daemon: a premium run that failed reports its error, and its model is checked after
- Daemon: Claude Code's stand-in for a failed API call is never taken for the model a run ran on
- Execution: forge's settings are read from its stdout alone, so a warning does not reset them
- Daemon: imd launch check runs the launch check on a repository, before there is a step to submit
- Daemon: a launch.json the verifier would reject is repaired on the worker, and never submitted
- Plane: launch_manifest_failed is a failure reason, the task's and never the machine's
- Worker: every prompt says the minutes the run has left, and a brief that waits on the clock asks
- Worker: a tests step sees what it reported and the answers before it reports again
- Dispatch: a step that reported findings is sent the answers on its next round, whatever its role
- Daemon: workers take no work until the runtime runs a shell command, rechecked on failure and daily
- Protocol: one GUIDANCE_MAX caps guidance, and a plan over it is refused at planning
- Daemon: imd doctor checks a runtime by having it run one shell command on its premium model
- Quotes: a repository whose foundry.toml the workers refuse to build is refused before anyone pays
- Verifier: a contract waiting for a library's address is named with the library, not as keccakHex
- Verifier: a hook placeholder spelled another way is refused with the spelling the deployer reads
- Verifier: a launch.json that does not parse is rejected before forge runs
- Execution: the launch manifest check is one implementation, shared by the verifier and the worker
